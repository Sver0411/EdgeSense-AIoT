## 冻结的设计决议

1. **主 RQ**：跨通道 + 跨节点证据能否区分"传感器故障"与"真实环境事件"（核心指标 = fault→event 误判率）。
   - 理由：SensorTrust 已占单通道故障检测，AdaptiveSense 已占变化感知采样，EventGuard 已占冗余预算。**只剩这个空白。**
2. **次级 RQ**：SQ1 trust 信号能否改善采样策略（S5 vs S6）；SQ2 边缘 vs 后端的代价与检出延迟。
3. **候选 RQ4 不作为 RQ**，降级为评测框架（trade-off 必须测但不占 RQ 名额）。
4. **B/C 必须同房间冗余部署（相隔 30–50 cm）**。分不同房间会让跨节点证据完全失效。
5. **整合策略 = 方案 C**：保持独立 repo，EdgeSense 以固定 commit **git subtree** vendor 引入 + `docs/vendored/*.md` 记录 SHA。理由：保留 Git history、研究清晰性（vendor SHA 即 baseline 出处）、作品集分工清楚。
6. **新贡献只集中在三处**：`edge/fusion/`、`backend/`、`copilot/`。其余全部是 vendor 或 baseline。
7. **故障注入与实验框架前移**（原 Phase 6/7 → Phase 3/4）。没有注入与框架就无法评估算法。
8. **控制路径架构上不存在**（不留 actuator 入口、API 只有 GET、写通路只在网关 ingest 内部）。

## 第二轮：Phase 0.1 Architecture Correction（同日）

用户 review 后提出 5 个修正，已完成：

1. **跨节点融合位置错误（硬伤）**：Phase 0 把 Cross-Node Fusion 画在 Sensor Node B/C 内部，
   但星型拓扑下节点拿不到邻节点数据。**已上移到 Gateway A**。
   节点侧闭环固定为：sensor acquisition → per-channel validity → SensorTrust → 跨通道融合 →
   本地变化检测 → 自适应采样 → LoRa transport。**v1 不引入 Gateway→Node 邻节点广播**。
2. **主 RQ 收窄**：`genuine environmental event` 定义过宽。改为只研究
   **`sensor_fault` vs `spatially shared environmental event`**。
   新增三分类：`sensor_fault` / `shared_event` / `localized_event`。
   **`localized_event` 排除出主 RQ 指标**（它在单节点视角下与 sensor_fault 原理上不可分辨），
   只作 stress test + limitation。不因此扩展成四分类系统。
3. **删除无依据门槛**：H1 的"fault→event 误判率相对下降 ≥ 50%"已删除（无先验依据，诱导事后挑口径）。
   改为报告：绝对值 / 绝对差 / 相对差 / 置信区间 / 逐场景结果；样本量允许时才用预先声明的统计检验。
4. **简化时间同步**：v1 只做 beacon + session id + 窗口配对(`(session_id, window_index)`，时间戳为辅)
   + timestamp tolerance。**线性漂移拟合降级为升级项**——先由 EXP-004 实测 offset/jitter/drift，
   只有数据表明简单同步不足时才引入。
5. **链路质量字段收窄**：v1 只记录包计数/序号缺口/重复/CRC/到达间隔/jitter。
   **RSSI 条件启用（未实测确认可读则 NULL）**，**SNR 直接不承诺**。
   任何 RF 指标必须经真实 E220 配置 + 真机日志验证后才能进 README claim。

## 第三轮：Phase 0.2 Final Design Freeze（同日）

修复用户指出的 5 个缺陷，并冻结 v1 架构：

- **F1 EXP-003 数据集逻辑错误（硬错误）**：原设计用 fault-only 数据集却报告 event→fault，分母为零。
  重建：fault 来自受控注入 + event 来自**真实物理干预**，event 标签为 `localized_event`，
  **明确声明不是 Primary RQ 的 shared-event 数据集**。新增门禁：`analyze_experiment.py` 在真值分母为 0 时**必须报错退出**。
- **F2 Cross-Channel(B2) claim 收窄**：禁止假设"单通道变化=故障、多通道同时变化=环境事件"。
  B2 重新定位为"提供额外 contextual evidence"。必须 4 个对抗性 fixture 通过
  （含 **I²C 总线级故障同时影响 SHT30+BH1750** 这个正向反例——它直接推翻原假设）。
  经来源隔离测试强制"不得读邻节点数据"。允许结果：有改善 / **无改善** / 只对某些 family 有改善。
- **F3 自适应采样下配对失效**：`(session_id, window_index)` + 隐含 seq 相等在 cadence 不同时破裂。
  改为 **gateway 定义的 fusion window → nearest valid sample → freshness 检查**。
  三态：`paired` / `partial_evidence` / `insufficient_alignment`。必须定义 `max_sample_age`。
  **明令禁止 `B.seq == C.seq` 作同步依据**；seq 只用于本节点去重与缺包检测。
  **配对可能性不变量 P0：`interval ≤ 2 × max_sample_age`**，超出即结构性降级，必须报告为自适应采样的代价。
  Primary RQ 阶段（EXP-004/005/006）用**固定密集 5 s** 隔离混淆变量；异步配对只在 EXP-007 验证。
- **F4 SQ2 降级**：删除 SQ2 作为研究问题 → **Engineering Evaluation E1**。
  **禁止**再写 "gateway-side avoids LoRa latency"——两者都在 LoRa 数据到达 gateway **之后**，
  差异只来自 serial uplink / backend processing / resource placement / **backend availability**。
- **F5 Fault Taxonomy 正交拆分**：`sensor_fault` / `network_fault` / `device_unavailable`。
  schema 拆出 `event_category` / `event_source` / `ground_truth_source` 三字段。
  `network_fault` → EXP-010；`device_unavailable` → availability/observability，**都不进 Primary RQ 指标**。
  另加公平性要求：B1 只声明 5 类（RANGE/STUCK/SPIKE/DRIFT/MISSING），
  OFFSET/NOISE/I²C/disconnect **不算 B1 失败**（记为 out of declared scope）。

**四项批准（blocker 全解除）**：B1 购置第二套 SHT30+BH1750（soil 不作 shared-event 通道）/
B2 `adaptive-lora-iot` 整体迁入且**不先建独立公开 repo**、保留原始数据与 provenance /
B3 主 RQ 收窄 / B4 保守表述，**禁止声称"适合日本部署"**。

**最终研究范围冻结**：Primary RQ = `sensor_fault` vs `spatially shared environmental event`；
Secondary RQ = trust-aware adaptive sampling。**只有 2 个 RQ，不再增加。**
AI Copilot / Dashboard / Backend **都不是研究贡献**，属 Engineering / FDE layer。

产出 `docs/PHASE_0_2_FINAL_DESIGN_FREEZE.md`（14 节 + 15 项 Before→After）。
